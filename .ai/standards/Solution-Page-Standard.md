# LFADJ Solution Page Standard

## 1. Purpose

Solution 页面用于回答客户的项目选择问题。

核心职责是帮助客户根据以下条件选择合适的移动照明解决方案：

- 项目环境
- 使用需求
- 运行条件
- 预算
- 维护要求

Solution 页面不是产品展示页面。

产品页面负责：

- 产品介绍
- 参数
- 产品优势
- 询盘转换

Solution 页面负责：

- 选择逻辑
- 应用判断
- 配置建议

## 2. Page Objectives

Solution 页面必须围绕一个明确的客户选择问题，帮助用户理解项目条件、判断适合的方案，并进入相关产品、应用或项目咨询路径。

页面目标包括：

- 回答客户正在解决的项目问题
- 说明影响选择的关键条件
- 提供基于项目条件的方案判断
- 建立相关产品、应用和解决方案之间的清晰内链
- 引导客户提交必要的项目信息

## 3. Core Principles

- One Page, One Purpose
- 内容必须真实、清晰并服务客户决策
- Solution 页面负责选择逻辑，不替代 Product 或 Application 页面
- 中英文页面必须保持核心信息一致并遵守语言隔离
- 页面结构、内容和内链必须支持 Google SEO 与 B2B 采购判断

## 4. Standard Page Structure

Solution Detail Page 固定结构为：

Hero

↓

Selection Factors

↓

LFADJ Recommended Solutions

↓

Related Products + Related Applications + Related Solutions

↓

CTA

结构要求：

- 各模块必须服务同一个客户问题
- 不得增加无意义模块
- 不得重复 Product 页面正文
- 不得写成长篇 Blog
- 不得与 Application 页面职责重叠

## 5. Hero Section

内容：

- Solution 标题
- 一句话说明客户问题
- 页面价值说明

## Solution Hero Standard V2

Desktop：

- Hero 使用左右两栏布局
- 左侧为 Breadcrumb、H1、副标题和 CTA
- 右侧为真实工程现场图片
- 文字区域约占 42%–45%
- 图片区域约占 55%–58%
- 左右内容保持视觉平衡

Mobile：

- 文字在上
- 图片在下
- 图片宽度 100%
- 不允许横向滚动
- H1、副标题和 CTA 必须保持清晰易读

Hero 图片规范：

- 使用真实工程现场图片
- 优先展示移动照明灯塔的实际应用
- 产品必须完整显示
- 灯具、灯杆、底盘、轮胎和支撑腿应清晰可见
- 产品约占画面宽度 30%–40%
- 产品四周保留合理空间
- 保留施工现场背景
- 推荐使用 16:9 或接近 16:9 的宽屏比例
- 不添加文字、Logo、水印或无关装饰
- 图片不得拉伸或变形
- 图片 alt 应描述实际应用场景和移动照明灯塔

## 6. Selection Factors Section

解释客户选择方案时需要考虑的因素：

- Project Environment
- Lighting Requirements
- Power Supply Conditions
- Operating Hours
- Maintenance Requirements

Selection Factors 用于帮助客户分析影响决策的主要项目条件。

标准要求：

- 通常使用 3–4 个因素
- 每个因素包含标题和简短说明
- 内容必须围绕客户项目条件
- 不得在此处提前堆叠产品推荐
- 不得写成技术百科
- 文案应便于客户快速扫描

## 7. Recommended Solutions Section

展示不同方案，例如：

- Diesel Mobile Lighting Solution
- Solar Mobile Lighting Solution

每个方案包含：

- Solution Name
- Project Conditions
- Suitable Applications
- Recommended Product

禁止重复出现 `LFADJ 建议：XXX 方案`。应避免方案标题和正文重复表达同一内容。

标准结构：

项目场景

↓

推荐方案

↓

简短说明

↓

Suitable For

每个推荐项必须包含：

1. Project Scenario
2. Recommended Solution
3. Short Explanation
4. Suitable For

规则：

- 推荐必须基于前一屏的 Selection Factors
- 推荐层级优先是解决方案，不是单纯罗列产品型号
- 产品型号可以在 Related Products 中承接
- 不得作出绝对适配承诺
- 不得暗示单一配置适合所有项目
- Suitable For 用于列出典型应用或项目类型
- 不得虚构具体项目数据

## 8. Related Products + CTA Section

产品只作为内部链接入口，不在 Solution 页面重复承担产品介绍职责。

例如：

- Diesel Solution → LF955 Diesel Mobile Light Tower
- Solar Solution → LF971 Solar Mobile Light Tower

最后一屏包含：

- Related Products
- Related Applications
- Related Solutions
- CTA

要求：

- Related Products 链接到相关产品页
- Related Applications 链接到相关应用页
- Related Solutions 链接到其他独立客户问题
- CTA 包含标题、简短描述、按钮
- CTA 按钮链接到对应语言 Contact 页面
- 中文页面只使用中文
- 英文页面只使用英文

### CTA

CTA 的目标是获取项目配置建议。

示例：`Request a Project Lighting Recommendation`

## 9. Google SEO Principles

Solution 页面的关键词目标包括：

- how to choose a light tower
- light tower selection guide
- mobile lighting solution
- project lighting requirements

页面重点是回答搜索用户的项目选择问题，不得堆砌产品关键词，也不得将 Solution 页面写成产品展示页面。

### Internal Linking Rules

Solution 页面必须连接：

- Products 页面
- Applications 页面
- Related Solutions 页面

链接目的：建立 LFADJ 网站主题权威，并帮助用户从选择逻辑自然进入相关产品、应用和解决方案页面。

所有链接还必须遵守 `SEO-Internal-Linking-Standard.md` 中适用于 Solution 页面的强制规则。

### Current Approved Example

当前已确认的参考页面：`How to Choose a Light Tower`。

该页面包含：

- 柴油移动照明方案
- 太阳能移动照明方案

后续其他 Solution 页面应参考本标准结构，并根据各自独立的页面职责和客户选择问题调整实际内容。

## 10. B2B Purchasing Logic

标准采购逻辑：

客户问题

↓

项目条件分析

↓

推荐方案

↓

适用场景判断

↓

相关产品与应用

↓

提交项目需求

Solution 页面必须帮助采购方判断：

- 是否适合
- 需要考虑哪些因素
- 哪类方案更匹配
- 下一步应提供哪些项目信息

## 11. Design Principles

- 页面保持简洁
- 每屏只承担一个明确职责
- 避免大面积无意义留白
- 卡片数量应受控
- 同一组卡片保持高度、间距和层级一致
- Desktop 与 Mobile 都必须易于扫描
- 不使用无意义动画
- 不使用过度装饰
- 不为了视觉增加无 SEO 或采购价值的模块

## 12. Pre-Publish Checklist

- 是否只有一个 H1
- H1 是否对应明确客户问题
- Hero 是否包含真实工程场景
- 产品是否完整显示
- 是否包含 Selection Factors
- 是否包含 Recommended Solutions
- 推荐项是否包含 Suitable For
- 是否包含 Products、Applications、Solutions 内链
- CTA 是否链接对应语言 Contact
- 中文和英文是否语言隔离
- Metadata 是否完整
- Canonical 是否正确
- hreflang 是否正确
- 图片 alt 是否准确
- 是否与已有 Solution 重复
- 是否存在关键词蚕食
- Desktop 与 Mobile 是否正常
- TypeScript 和 Build 是否通过

## Solutions Hub Standard V1

适用页面：

- 中文：`/zh/solutions`
- 英文：`/en/solutions`

Solutions Hub 是全部 Solution 页面的导航中心，用于帮助客户根据采购问题进入对应的解决方案，并向 Solution 详情页传递内部链接。Solutions Hub 不承担完整回答单一选型问题或介绍具体产品的职责。

### 6.1 Standard Page Structure

所有 Solutions 首页默认采用以下三个主要 Section：

1. Hero
2. Solution Navigation
3. Related Products + CTA

不得新增没有明确用户价值、SEO 职责或采购导航目的的主要 Section。

### 6.2 Hero Section

Hero 包含：

- Breadcrumb
- 一个 H1
- 一句话价值描述

Hero 用于说明 Solutions Hub 的页面职责和用户价值，不展开各 Solution 的完整正文，不添加产品型号或多余 CTA。

### 6.3 Solution Navigation Section

Section 标题应以客户采购选择为导向：

- 中文：`根据您的项目选择合适的解决方案`
- 英文：`Choose the Right Solution for Your Project`

Solutions Hub Standard V1 包含以下四个已确认的 Solution 入口：

1. 如何为项目选择合适的移动照明灯塔
2. 如何选择合适的移动照明灯塔升降系统
3. 如何选择合适的移动照明灯塔动力系统
4. 如何选择适合恶劣环境的移动照明灯塔

每个入口采用简洁卡片，只包含 Solution 标题、一句简短说明和真实可访问的详情页链接。不得新增占位卡片、失效链接或未完成 Solution。

### 6.4 Related Products + CTA Section

Related Products 与 CTA 必须位于同一个主要 Section。

Related Products 仅作为真实产品页的简洁内部链接入口，不复制产品详情、参数或产品优势。

CTA 用于引导客户提交项目条件并获取项目配置建议。CTA 应保持紧凑，只保留一个主要按钮，并链接到当前语言的 Contact 页面。

### 6.5 Content Boundaries

Solutions Hub 不得：

- 增加无意义内容模块
- 重复 Solution 详情页正文
- 写成长篇 Blog
- 增加占位内容或占位链接
- 与 Product 页面职责重叠
- 堆砌关键词或产品型号
- 破坏中英文语言隔离

Solutions Hub 必须保持 Topic Cluster 中心职责，通过清晰、真实且同语言的内部链接连接 Solution 详情页、相关产品页和 Contact 页面。
